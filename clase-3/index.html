Buscar por significado, no por palabras

Búsqueda léxica (BM25)

Coincidencia de tokens.

"auto" no encuentra "coche".

"cómo cancelo mi plan" no encuentra "baja de suscripción".

Búsqueda semántica

Coincidencia de significado.

"auto" ≈ "coche" ≈ "vehículo".

Funciona con paráfrasis, sinónimos e incluso otros idiomas.

Idea central: si el significado es un punto en un espacio, buscar es encontrar los puntos más cercanos.

De texto a vectores

  • Un embedding convierte texto en un vector de dimensión fija: 384, 768, 1024…
  • En la clase 1 vimos embeddings por token. Ahora queremos uno por frase o párrafo.
  • Textos con significado parecido quedan cerca.
model.encode("cómo cancelo mi plan")
→ [0.12, -0.48, 0.07, …]  # 384 dims

Modelos Encoder-Only

  • La otra mitad del Transformer: sin decoder, sin generación.
  • Cada token ve a todos los demás: entiende contexto en ambas direcciones.
  • Pooling: de N vectores (uno por token) a uno solo. Lo más común es el promedio (mean pooling).
  • BERT "crudo" da malos embeddings de frase: hace falta entrenarlo para similitud.

Dimensión

Más dimensiones: más capacidad, pero más memoria y cómputo.

Normalización

Con norma 1, el producto punto es la similitud coseno.

Un modelo, un espacio

El clásico rey − hombre + mujer ≈ reina: las direcciones del espacio codifican relaciones.

¿Qué tan cerca están dos vectores?

Similitud coseno

cos(a,b) = a·b / (|a||b|)

Mide el ángulo. La más usada.

Producto punto

a·b

Con vectores normalizados es igual al coseno, y más barato.

Euclidiana

|a − b|

Distancia "en línea recta". Con normalización, ordena igual.

kNN exacto

Comparar la query contra todos los vectores y quedarse con los k mejores: O(N).

1M de documentos × 768 dims ≈ 768M multiplicaciones por consulta. No escala.

Chunking: ¿Por qué dividir documentos?

ayuda.md · Centro de ayuda

chunk 1 · facturaciónLas facturas se emiten el día 1 de cada mes y llegan por email. Podés descargarlas desde Configuración → Pagos.

chunk 2 · baja del planPara dar de baja tu plan, entrá a Configuración → Suscripción. La baja se hace efectiva al final del período facturado.

chunk 3 · envíosLos envíos dentro de CABA tardan entre 24 y 48 h. Al interior del país, entre 3 y 5 días hábiles.

chunk 4 · contraseñaSi olvidaste tu contraseña, usá "Recuperar acceso". Te enviamos un enlace válido por 30 minutos.

  • El encoder tiene límite de tokens (ej. 512).
  • Un vector para un documento entero diluye el significado: mezcla todos los temas.
  • Con chunks, cada vector representa una sola idea.

Chunk chico

Preciso, pero sin contexto.

Chunk grande

Con contexto, pero ruidoso.

No hay tamaño universal: se elige evaluando con tus propios datos.

Estrategias de Chunking

Tamaño fijo + overlap

N tokens con solapamiento. Simple y sorprendentemente bueno.

Recursivo

Párrafos → oraciones → caracteres, hasta que entre.

Por formato

Headers de Markdown, secciones HTML, funciones de código, tablas.

Semántico

Cortar donde cambia el tema, usando embeddings.

Parent-child

Buscar con chunks chicos, devolver el bloque grande.

Enriquecido

Agregar título, sección o un resumen del contexto al chunk.

RAG (Retrieval-Augmented Generation)

El problema

  • El LLM no conoce tus datos.
  • Tiene fecha de corte.
  • Cuando no sabe, alucina.

La idea

Primero buscar lo relevante y después generar con ese contexto en el prompt.

Datos actualizados, citas y control de acceso.

Límite: si el retrieval falla, la respuesta falla. Garbage in, garbage out.

Pipeline de RAG · Indexación

INDEXACIÓN · OFFLINE

1 · Documentos

Juntamos las fuentes de conocimiento: PDFs, wikis, tickets, páginas de ayuda, código.

ayuda.md
terminos.pdf
faq.html

2 · Parsing

Extraemos el texto útil: sacamos menús y encabezados repetidos, pasamos tablas a texto.

# Baja del plan
Para dar de baja tu plan, entrá a
Configuración → Suscripción…

3 · Chunking

Dividimos el texto en chunks. Cada uno debería hablar de un solo tema.

chunk 1 · facturación
chunk 2 · baja del plan
chunk 3 · envíos
chunk 4 · contraseña

4 · Embeddings

Cada chunk pasa por el encoder y sale un vector de tamaño fijo.

chunk 2 → [0.12, -0.48, 0.07, …]
          384 dimensiones

5 · Vector DB

Guardamos vector, texto y metadata. La DB arma el índice para buscar rápido.

{ "id": "ayuda#2",
  "vector": [0.12, -0.48, …],
  "text": "Para dar de baja…",
  "source": "ayuda.md" }

Se hace una vez, y de nuevo cuando cambian los documentos.

Pipeline de RAG · Consulta

CONSULTA · ONLINE

1 · Pregunta

Llega la pregunta tal como la escribió el usuario.

"¿Cómo doy de baja mi plan?"

2 · Rewriting

Un LLM la reformula para que busque mejor: sin ambigüedad, con sinónimos.

"cancelar suscripción / baja del plan"

3 · Búsqueda

Se vectoriza con el mismo modelo y se busca en la Vector DB, combinando semántica y BM25.

→ top-50 candidatos

4 · Reranking

Un cross-encoder reordena los candidatos con más precisión. Nos quedamos con los mejores.

1. baja del plan   0.94
2. facturación     0.41
3. contraseña      0.12

5 · Prompt

Armamos el prompt: instrucciones, los chunks recuperados y la pregunta.

[system] Respondé solo con el contexto.
[1] Para dar de baja tu plan…
[pregunta] ¿Cómo doy de baja mi plan?

6 · LLM

El LLM redacta la respuesta apoyándose en el contexto, no en su memoria.

→ generación token a token

7 · Respuesta

Devolvemos la respuesta con referencias a las fuentes.

"Entrá a Configuración → Suscripción [1].
 La baja se aplica al final del período [1]."

Se hace en cada pregunta. La búsqueda usa la Vector DB que armó la indexación.

Arquitectura de un pipeline de RAG

A llega un documento nuevo · B el job lo divide en chunks y pide sus vectores a la API · C guarda texto + vector + metadata en pgvector.

1 pregunta · 2 el agente embebe la pregunta · 3 busca el top-5 en pgvector · 4 arma el prompt y llama al LLM · 5 responde con citas.

El prompt

# system
Respondé usando solo el contexto. Si la respuesta no está, decí que no lo sabés.
Citá la fuente de cada afirmación como [n].

# contexto (top-5 del reranker)
[1] faq.pdf  · "Para dar de baja tu plan, entrá a Configuración → Suscripción…"
[2] terminos.md · "La baja se hace efectiva al final del período facturado…"

# pregunta
¿Cómo cancelo mi plan y cuándo deja de cobrarse?

En vivo: el LLM decide cuándo y qué buscar usando la búsqueda como una tool. Puente a la próxima clase.

Cuando falla, ¿dónde mirar?

No lo encontró

Chunking, modelo de embeddings o falta búsqueda híbrida.

Lo encontró, quedó abajo

Falta reranking, o el k es muy chico.

Lo tenía y lo ignoró

Prompt, demasiado contexto o modelo débil.

Evaluar de punta a punta

Faithfulness (¿se apoya en el contexto?) · Relevancia de la respuesta · LLM-as-judge · frameworks como RAGAS.

MCP Servers

Darle herramientas a un agente,

MCP: el problema de las N × M integraciones

MCP (Model Context Protocol): protocolo abierto, publicado por Anthropic en 2024. Cada herramienta se escribe una vez y la usa cualquier app compatible: "el USB-C de las apps de IA".

Caso de uso: nuestro RAG como tool

agente piensaNecesito buscar en la documentación.
tool callbuscar_documentacion(query="baja del plan")
resultado[1] Para dar de baja tu plan, entrá a Configuración → Suscripción…
respuestaEntrá a Configuración → Suscripción [1].

El agente decide cuándo buscar y con qué texto, en vez de buscar siempre: agentic RAG.

Arquitectura de MCP

Tools

Acciones. El modelo decide cuándo usarlas: buscar, crear un ticket.

Resources

Datos de solo lectura. La app decide cuándo cargarlos: un archivo, un esquema.

Prompts

Plantillas reutilizables. El usuario las elige: "resumí este ticket".

Cómo hablan: JSON-RPC 2.0

CLIENT ↔ SERVER

1 · server/discover

El client le pregunta al server qué versiones y capacidades soporta. Es opcional: también puede llamar directo.

→ {"jsonrpc": "2.0", "id": 1, "method": "server/discover"}
← {"jsonrpc": "2.0", "id": 1, "result": {
     "capabilities": { "tools": {} }, … } }

2 · tools/list

El client pide la lista de tools. Cada una trae nombre, descripción y JSON Schema de sus argumentos.

← { "tools": [ {
    "name": "buscar_documentacion",
    "description": "Busca en el centro de ayuda…",
    "inputSchema": { "type": "object",
      "properties": { "query": { "type": "string" } },
      "required": ["query"] } } ] }

3 · El LLM elige

El host le pasa esas tools al LLM. El modelo responde pidiendo usar una, con sus argumentos.

tool_use:
  name:  buscar_documentacion
  input: { "query": "baja del plan" }

4 · tools/call

El client manda la llamada al server. Cada request lleva su versión y capacidades en _meta.

→ { "jsonrpc": "2.0", "id": 3, "method": "tools/call",
  "params": {
    "name": "buscar_documentacion",
    "arguments": { "query": "baja del plan" },
  "_meta": {
    "io.modelcontextprotocol/protocolVersion": "2026-07-28",
    "io.modelcontextprotocol/clientCapabilities": {} } } }

5 · Resultado

El server ejecuta la búsqueda y devuelve el contenido. El host lo agrega al contexto del LLM.

← { "jsonrpc": "2.0", "id": 3, "result": {
    "resultType": "complete",
    "content": [ { "type": "text",
      "text": "[1] Para dar de baja tu plan…" } ] } }

Desde la revisión 2026-07-28 el protocolo es stateless: no hay handshake inicial, cada request viaja con su contexto. JSON simplificado.

if __name__ == "__main__":

Cómo se expone

stdio · local

El host lanza el server como un proceso y le habla por entrada/salida estándar.

Config del host (ej. Claude Desktop):

{ "mcpServers": {
    "ayuda": {
      "command": "uv",
      "args": ["run", "server.py"] } } }

Ideal para desarrollo y herramientas de escritorio.

Streamable HTTP · remoto

El server corre como un servicio web: cada mensaje es un POST a un endpoint.

Mismo server, otro transporte:

mcp.run(transport="streamable-http",
        port=8000)
# → https://ayuda.miempresa.com/mcp

Con autenticación (OAuth): para compartirlo con un equipo o producto.

⚠ Lo que devuelve una tool entra al contexto del modelo: mínimo privilegio y cuidado con prompt injection. Hay servers listos para GitHub, Postgres, Slack, Drive…

Escalar: muchos agentes, un solo MCP

Sin MCP: 4 agentes × 3 sistemas = 12 conectores. Con MCP: cada sistema se conecta una vez y todos los agentes usan el mismo servidor. Un cambio (otro modelo de embeddings, un permiso) se hace en un solo lugar.
